# Pet Halo 0.1.0 Beta 4

Pet Halo is an independent, unofficial macOS companion for Codex. Beta 4
restores the Pet Ring arc opening for the current Codex Desktop layout while
preserving the existing Pet center, visual-center calibration, Usage
presentation, and fallback hierarchy.

## Highlights

- Activity cards above the Pet select the upper arc opening, and activity cards
  below the Pet select the lower arc opening.
- The current Codex Desktop Pet-spanning Accessibility container is excluded
  from activity-direction resolution.
- Narrow voice and resize controls are excluded from activity-direction
  resolution.
- Multiple activity cards on the same side are treated as one directional
  stack. Mixed-side activity remains ambiguous and retains the prior opening
  instead of guessing.
- Pet selection, midpoint tracking, saved visual-center offset, ring radii,
  Usage semantics, and the Pet → calibrated-window → free-floating hierarchy
  are unchanged.

## Compatibility boundary

The candidate was prepared against Codex Desktop `26.727.40816 (6067)`. Pet
Halo reads only the existing Accessibility window role, subrole, visibility,
position, and size geometry required by Pet following. It does not inspect
window titles, conversation content, screenshots, or OCR.

## Requirements

- macOS 14.0 or later on Apple silicon or Intel.
- Supported Codex CLI and Desktop versions listed in `docs/COMPATIBILITY.md`.
- Accessibility permission only when following is enabled.

## Distribution boundary

This is Beta software distributed as an **Unsigned Developer Preview**. The
manually gated GitHub workflow publishes it only from reviewed `main`, with the
new `v0.1.0-beta.4` tag and bundle build `4`, after the unsigned artifact,
manifest, release notes, checksums, and source commit pass validation.

`Pet-Halo-0.1.0-beta.4-unsigned-universal.zip` is not signed with a Developer ID
certificate and is not notarized by Apple. macOS may block its first launch.
Verify `SHA256SUMS`, the GitHub source, and repository provenance before deciding
whether to override Gatekeeper. A future signed/notarized artifact must use a
new tag and build number; it must not replace this release.
